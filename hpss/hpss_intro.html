Introduction to HPSS at NERSC#

NERSC provides an archive (currently tape) for long-term storage of data: HPSS, the High Performance Storage System. Individual users may store data in their own area, or request storage for files meant for widespread DESC Working Group or Collaboration use by opening an issue on desc-help.

HPSS is a good way to back up your files and to recover from purging on Perlmutter $PSCRATCH.

Tools for Working with HPSS#

  • Writing to HPSS: use the NERSC command-line tools htar (bundles files into a tar archive written directly to HPSS) and hsi (general HPSS commands such as put, get, ls, mkdir, mv, and rm).

  • Reading from HPSS: the recommended method is Globus, using the NERSC HPSS collection. See Using Globus to Access the DESC HPSS Project Area for step-by-step instructions.

  • Batch jobs: run HPSS transfers in the xfer queue (#SBATCH -q xfer), which is free of charge. Over-estimate the job’s time limit rather than risk running out of time. See the example job scripts in Time Domain WG HPSS Area.

Best Practices#

  • Use hsi for large files (at least > 1 GB). Copy them into HPSS individually with hsi put.

  • Use htar for many small files. Sending many small (< 1 MB) files to HPSS individually significantly degrades tape performance and makes backups very slow. Bundle them with htar (or tar) instead, subject to the limitations below.

  • Avoid very large files. Files larger than 2 TB are difficult for HPSS to handle, and NERSC may terminate transfers of files 20 TB or larger. Split large data into smaller chunks (e.g. 500 GB) before archiving; see NERSC’s guidance to avoid very large files.

  • Generate checksums. Pass -Hcrc to htar so checksums are stored with the archive.

  • Existing data cannot be overwritten. To update data, write a new copy and then remove or rename the old one with hsi rm / hsi mv.

Warning

Files deleted from HPSS cannot be recovered.

Limitations of htar#

htar is suitable for storing many small files, with the following restrictions (from the NERSC archive documentation):

Limit

Details

Aggregate (archive) size

NERSC recommends htar aggregates between 100 GB and 2 TB

Individual member file size

The maximum size of any one file inside a bundle is 68 GB. This is not a limit on the size of the whole bundle

Path length

Bundles cannot contain directory paths longer than 154 characters

File name length

Bundles cannot contain file names longer than 99 characters

If you wish to archive bundles of files that exceed any of these limits, the easiest option is to bundle them first with regular tar and then use hsi put to store the resulting tarball in HPSS. See If You Have Paths > 154 Characters or Filenames > 99 Characters for an example job script.
